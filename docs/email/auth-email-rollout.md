# Lot Logic authentication email rollout (PR #32)

## Architecture
- Supabase Auth remains the source of verification tokens and user identity.
- Supabase **Send Email Hook** runs the signed Edge Function in supabase/functions/send-email/.
- The hook verifies Standard Webhooks signatures, renders version-controlled HTML and plaintext, and submits messages to Resend.
- From: Lot Logic Accounts <accounts@yourlotlogic.com>
- Reply-To: support@yourlotlogic.com (hosted at Porkbun).
- Password recovery and invites return to /set-password; signup goes to /onboarding; magic links to /evaluate.
- The production and preview projects MUST use separate hook deployments, secrets, and LOT_LOGIC_AUTH_ORIGIN values.

## Required Supabase Edge Function secrets (set per project; never commit values)
- RESEND_API_KEY: valid Resend key authorized for yourlotlogic.com; use separate credentials for preview if possible.
- SEND_EMAIL_HOOK_SECRET: generated by the **same Supabase project's** Auth Hooks settings when choosing HTTPS Send Email Hook. Signature verification is mandatory.
- LOT_LOGIC_AUTH_ORIGIN:
  - production: https://yourlotlogic.com
  - preview: https://deploy-preview-32--mmav.netlify.app (or currently selected canonical preview alias)

## Pre-activation checks
1. Ensure accounts@yourlotlogic.com is an authorized sender for the verified Resend domain. It does not require a Porkbun mailbox.
2. Keep existing Porkbun/resend SPF, DKIM and DMARC records unchanged. They already passed live authentication.
3. In the PREVIEW Supabase project (xqrtiuddzvyfgubqqnzx), deploy send-email with JWT verification **disabled** (it is authenticated with the Standard Webhooks signature instead). The function MUST NOT be exposed as an unsigned public mailer.
4. Set its three secrets, then select the function HTTPS URL as the Send Email Hook endpoint in Auth > Hooks. Use Supabase-generated hook secret in the function config.
5. Verify preview Supabase Auth has preview Site URL and Redirect URL allowlisting. Configure signups to go to preview domains, not production.
6. Complete preview signup, OTP/magic-link, invite, password recovery, and email-change flows. Inspect links, email headers, and actual landing behavior. Confirm no sensitive auth tokens appear in logs.
7. Test Resend delivery to Yahoo and Gmail. Delivered status does NOT equal inbox placement.
8. Only AFTER preview is verified, separately deploy/configure the production Supabase function and activate the production hook. Avoid production changes until approved.

## Operational considerations
- When the Send Email Hook is active, it replaces SMTP delivery for supported Supabase Auth emails.
- The function returns non-2xx if Resend fails; Auth sending then fails rather than silently dropping the message.
- For secure email change Supabase may provide two hashes: token_hash_new for the CURRENT email and token_hash for the NEW email. Regression checks verify this mapping.
- Use distinct API keys or controlled sender destinations for preview and production to avoid accidental emails.
- Email templates are source-controlled; the Resend dashboard remains the delivery/observability surface, not the code source.
- Current branch change does not enable the hook in either Supabase project and does not modify production SMTP or DNS.
- This hook does not yet implement retry-idempotency for a partial two-message secure email-change send; confirm platform retry behavior before production rollout.
